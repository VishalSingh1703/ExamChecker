VIVA mode for ExamChecker

The Practice paper you already generate from a chapter PDF, delivered aloud. Murf reads each question, Sarvam transcribes the spoken answer into the answer box, and the existing Gemini grader marks the transcript. Voice stack lifted from Guardian, minus telephony.

Pipecat WebSocket Silence capture + Next English (en-IN) Local Python service Not Vercel-deployable yet
01

What already exists, and what changes

Practice is a seven-phase machine. Viva forks it at exactly one point — the answering step — and rejoins before grading. Source, Blueprint and Generate are untouched, and so is everything downstream of the transcript.

02

How the browser and the voice service talk

Guardian's audio arrived from Twilio as µ-law 8 kHz and was decoded by TwilioFrameSerializer. That entire layer disappears. In its place: one WebSocket from the browser carrying protobuf-framed PCM and the RTVI control messages, so there is no second connection to keep alive.

03

One question, start to finish

The state machine inside VivaOrchestrator. The mic is closed while the examiner speaks, opens the moment the audio finishes playing, and an answer is only ever captured — never auto-advanced. The student commits with a button press.

Why capture, not auto-advance

A viva answer has thinking pauses. Auto-advancing on silence cuts students off mid-sentence and there is no way back. Capture is recoverable — speaking again re-opens the buffer and the answer keeps growing.

Echo is the real risk

Murf's voice coming out of the speaker and back into the mic would be transcribed as the student's answer. Guarded twice — browser echoCancellation, and InputAudioGate dropping every input frame unless the state is listening. Guardian wrote this gate and never wired it in; here it is load-bearing.

Scope line

The box simply shows what Sarvam heard — partial while speaking, transcript when final. Making it hand-editable is a separate frontend workstream and is deliberately out of scope here. Keeping this side dumb means the answer the grader sees is exactly the answer the server captured.

  • Past answers are read-only. Rendered collapsed below, so irreversibility is visible rather than merely enforced.
  • Next is enabled once the answer is captured.
  • The overall timer stays. Reuses the existing useCountdown and deadlineAt, so the auto-submit safety net still works.
  • If the socket drops, an alert offers Switch to typed test — the paper and every answer so far survive.

app/viva/service.py · the pipeline, with the four deliberate changes from Guardian
transport = FastAPIWebsocketTransport(websocket, params=FastAPIWebsocketParams(
    serializer=ProtobufFrameSerializer(),        # ← was TwilioFrameSerializer
    audio_in_enabled=True, audio_out_enabled=True, add_wav_header=False,
    audio_in_sample_rate=16000,                 # ← was 8000 (µ-law telephony)
    audio_out_sample_rate=24000,
))

vad = VADProcessor(vad_analyzer=SileroVADAnalyzer(params=VADParams(...)))
                                                 # ← no sample_rate= pin. see note below

stt = SarvamSTTService(api_key=settings.SARVAM_API_KEY, settings=SarvamSTTService.Settings(
    model="saarika:v2.5", language=Language.EN_IN,
    vad_signals=False, high_vad_sensitivity=False,
), keepalive_timeout=10.0, ttfs_p99_latency=0.35)

tts = MurfTTSService(api_key=settings.MURF_API_KEY, params=MurfTTSService.InputParams(
    voice_id=..., style=..., rate=..., pitch=..., variation=...,
    sample_rate=24000, format="PCM", model="falcon-2",
    multi_native_locale=murf["locale"],       # ← Guardian passes locale=, silently dropped
))

pipeline = Pipeline([
    transport.input(),
    rtvi,                 # RTVIProcessor — carries the control messages
    gate,                 # drops InputAudioRawFrame unless state == listening
    vad, stt,
    orch,                 # VivaOrchestrator — pushes TTSSpeakFrame(question)
    tts,
    transport.output(),
    SpeechWatcher(orch),  # BotStoppedSpeakingFrame → orch.on_bot_finished()
])

task = PipelineTask(pipeline,
    params=PipelineParams(enable_metrics=True, enable_usage_metrics=True),
    observers=[RTVIObserver(rtvi)])
await PipelineRunner(handle_sigint=False).run(task)

Two Guardian bugs not to carry over

1. MurfTTSService.InputParams has no locale field — it is multi_native_locale. Guardian sets res["locale"] and passes locale=; pydantic ignores the extra, so the configured language never actually reaches Murf.

2. Guardian pins SileroVADAnalyzer(sample_rate=8000) while its serializer up-converts and feeds the pipeline at 16 kHz, so the VAD analyses at the wrong rate. Leave sample_rate off the analyzer and let the StartFrame set it.

The record keeps kind: 'practice' on purpose

buildPracticeRecord('viva') sets examTitle: 'Viva — <chapter>', term: 'Viva' and studentSection: 'Viva Practice', but leaves kind alone. CLAUDE.md's invariant is that every loadReports() caller filters on kind, and AnalyticsView filters with kind !== 'practice' — so introducing kind: 'viva' would silently leak viva attempts into the teacher's analytics. Keeping 'practice' means History and Analytics need zero changes.

08

How we'll know it works

  1. cd python && uv venv && uv pip install -r requirements.txt, fill .env, python run.py → curl localhost:8080/health returns ok.
  2. VITE_VIVA_WS_URL=ws://localhost:8080/ws/viva npm start
  3. Practice → chapter PDF → blueprint 3 × 2 marks → Preview → Viva → Start.
  4. In order: mic prompt → Murf speaks Q1 → pill flips to Listening → words appear as you talk → ~2.5 s quiet → Captured → edit by hand → Next → Q2 is spoken.
  5. Irreversibility: no control offers Q1 again, and a hand-crafted viva:next {index:0} is rejected by the server.
  6. Finish & Mark → Gemini grades the transcripts → the standard RecordDetail report renders → appears under History → Practice, and not in Analytics.
  7. npm run build passes — strict TS, noUnusedLocals.
  8. Failure paths: kill run.py mid-viva → banner + working Switch to typed test; reload mid-viva → returns to the viva phase with prior answers intact.

Risks worth naming

  • Silence threshold is a guess. 2.5 s will clip a student pausing to think. Recoverable, and VIVA_ANSWER_SILENCE_SECS is env-tunable.
  • Sarvam at 16 kHz is untested. Guardian only ever ran saarika:v2.5 at 8 kHz over telephony. Better input, new path.
  • 25-question cap still applies — gradeExtractedText runs at maxOutputTokens: 1024.

Hosting, deferred by choice

A long-lived WebSocket server cannot run on Vercel. The Viva option hides itself when VITE_VIVA_WS_URL is unset, so the production build is completely unaffected until a host is picked — Render / Railway / Fly, plus wss://, an origin allowlist and a handshake secret so the Sarvam and Murf keys aren't open to the internet.
